# 指定网络下载器

Windows 桌面下载工具，C# / .NET 10 / WPF，无第三方 NuGet 依赖。支持指定网卡、多连接分片下载、暂停和断点续传。

## 运行

安装 .NET 10 Desktop Runtime 后，打开 `publish/NetworkDownloader.exe`。
开发运行：

```powershell
dotnet run --project NetworkDownloader.App
```

1. 输入 HTTP/HTTPS 文件直链。
2. 选择以太网或 Wi-Fi 网卡，下拉列表和选中状态均只显示“网卡名称 · IPv4 地址”；选择 1、2、4、8、16 个下载连接，默认 4 个。
3. 选择保存目录，程序自动从下载地址路径末段解析文件名，点击“开始下载 / 继续”。地址中的查询参数、片段不会包含在文件名中，中文和空格会解码；地址不含文件名时使用 `download.bin`。
4. 同名成品已存在时自动保存为 `文件名 (1).扩展名`，不覆盖已有文件。单连接下载保留 `文件名.part` 和 `文件名.part.json`；多连接下载还会保存 `文件名.part.segments` 分片目录。相同 URL、目录再次开始即可找到临时文件续传；也可暂停后换网卡或调整连接数再继续。
5. DHCP 地址变化后先刷新网卡。关闭窗口会取消请求、关闭文件后退出。

文件名中的 Windows 非法字符会替换为下划线，保留名称会加下划线前缀，防止地址被解析为目录。原有版本保存的完整文件路径会自动迁移为其所在目录。请保管好 `.part.json`：其中包含原始下载 URL，签名链接也可能含有访问令牌。设置位于 `%LOCALAPPDATA%/NetworkDownloader/settings.json`，带查询参数或账号信息的地址不会写入设置；重启后需重新粘贴此类地址。

界面采用紧凑布局，输入框、下拉框和按钮统一为 32 个设备无关像素高，文字、图标、圆角及间距同步缩小；长网卡名称可悬停查看完整名称和 IP。

## 网络选择的实现与边界

- `SocketsHttpHandler.ConnectCallback` 创建 IPv4 TCP Socket，设置 Windows `IP_UNICAST_IF`（网卡索引，网络字节序），并 `Bind` 到所选本地 IP，然后连接目标地址。
- 重定向建立的新连接仍使用同一个连接回调。所有分片均使用同一个绑定网卡的客户端；分片请求使用 HTTP/1.1，确保并行范围请求建立独立 TCP 连接。单连接下载也可使用 HTTP/2。禁用代理和 HTTP/3。系统路由表和其他应用不受修改，不需要管理员权限。
- 所选接口没有可用路由、网关或公网能力时下载失败；不会自动创建未绑定 Socket 来切换网络。应用不能绕过网络自身的访问限制。
- DNS 调用系统解析器，DNS 查询可能经过其他接口。VPN、企业过滤驱动以及系统隧道仍可能影响实际物理出口；本工具没有提供驱动级隔离。
- 当前支持 IPv4、有线 / Wi-Fi 列表、单任务和多连接分片下载。无 IPv4 的网络、纯 IPv6 服务器、网页解析、登录交互、队列与限速尚未实现。
- 同一个 Socket 不能在连接中途切换网卡；暂停后重新连接，可使用新选择的网卡续传。

## 多连接下载

- 发出 `Range: bytes=0-0` 探测请求，只有服务器返回合法的 `206`、总长度及强 ETag / Last-Modified 时才启用分片。
- 文件小于 512 KB、服务器不支持范围请求、无法安全确认文件版本时，自动回退单连接。每个分片至少约 256 KB，实际并发数可能小于选择值。
- 根据总长度划分连续、不重叠的字节范围，最多同时执行所选数量的异步网络请求。各分片独立写入磁盘，进度和速度按所有分片汇总。
- 暂停、退出或传输中断后保留每个分片的已下载字节。恢复时验证远程版本并从每个分片的真实长度继续；已完成分片不重新下载。调整连接数只改变并发上限，已有分片布局保持不变。
- 文件版本变化时重新下载分片；服务器在探测后拒绝分片时，取消并等待其他分片停止，再安全回退单连接。旧版单连接临时文件仍以单连接方式续传，不丢弃已有进度。
- 每个分片分别检查 `Content-Range`、验证标识和实际长度，传输失败最多重试两次。任一分片发生不可恢复错误时取消其他分片，不生成成品。
- 全部分片完成后按字节顺序流式合并，再重命名为最终文件。合并中取消可在下次直接使用已完成分片重新合并。合并期间需同时保存分片和合并文件，临时磁盘空间约为文件大小的两倍。
- 下载任务使用独占临时锁，避免两个新版进程同时写入相同目标。分片目录只清理约定名称的临时文件，不递归删除未知文件。
- 多连接不保证成倍提速，实际速度取决于服务端限制、可用带宽和磁盘性能；只使用选择的网卡，不合并两张网卡的带宽。

## 文件完整性与恢复

- 使用流式 I/O 和 128 KB 缓冲区，不把大文件整体加载到内存。
- 使用强 ETag 或 Last-Modified 配合 Range / If-Range；没有验证标识时从头下载，避免混合不同版本。
- 只有合法的 `206 Content-Range` 才追加；`200` 从头下载，`416` 重新请求完整文件，不把现有临时文件直接判为成功。
- 校验续传偏移、范围、文件总长度、服务端返回的验证标识。声明长度不完整时不生成最终文件。未知长度响应以正常 EOF 为完成条件；没有服务端校验和时无法证明内容级完整性。
- 拒绝压缩传输，防止 Range 字节偏移和本地文件字节数不一致。HTTP 错误不会保存为成品文件。
- 连接 / 响应头约 20–30 秒超时，流式读取 30 秒无数据超时；传输错误最多自动重试两次，暂停可取消重试等待。
- 文件完成后在同一目录重命名 `.part` 为最终文件。续传需要保留元数据及相应的临时文件 / 分片目录，损坏或不匹配的元数据会报错。

## 构建与验证

```powershell
dotnet build NetworkDownloader.slnx -c Release
dotnet run --project NetworkDownloader.Tests -c Release
dotnet publish NetworkDownloader.App -c Release --self-contained false -o publish
```

测试程序不依赖测试框架或公网，验证目录保存、URL 文件名解析、中文解码、同名编号、临时文件查找、完整下载、续传、取消恢复、资源变化、非法 Range、416、错误响应、目标文件保护，以及真实并发、分片合并、并发数变更、单连接回退、分片中断重试和合并取消恢复。通过真实本地 TCP 服务验证单连接和多连接均绑定指定 Windows 网卡地址，下载结果用 SHA-256 对比测试源数据。

2026-10-28 在 Windows / .NET SDK 10.0.400 验证：Release 构建零警告、零错误；41 项测试全部通过，其中包括真实多 TCP 连接并发及源地址绑定测试。`NetworkDownloader-win-x64.zip` 为当前 Windows x64 环境的框架依赖版本，解压后运行，需 .NET 10 Desktop Runtime。也可以自行使用 `-r win-x64 --self-contained true` 发布包含运行时的版本（首次可能需要联网下载运行时包）。

真实双网卡验收：在两张网卡均有公网时分别下载同一文件，使用资源监视器 / Wireshark 核对本地源 IP、网卡流量；如两张网卡的 NAT 出口不同，也可使用自己信任的公网 IP 回显服务核对出口。下载时断开所选网卡，应失败 / 重试并保留临时文件；暂停后改选另一张网卡应能续传。实际物理双网卡出口需要在目标网络环境中验证。

## 项目结构

- `NetworkDownloader.App`：中文 WPF 界面、网卡 / 连接数选择、目录保存、暂停、状态显示与设置。
- `NetworkDownloader.Core`：网卡枚举、Socket 绑定、流式下载、分片并发调度、合并和续传校验。
- `NetworkDownloader.Tests`：离线回归测试及 Windows Socket 集成测试。
