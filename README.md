# 指定网络下载器

Windows 桌面下载工具，C# / .NET 10 / WPF。支持分类任务列表、SQLite 持久化、多任务排队、每任务指定 IPv4 网卡、HTTP 多连接分片和磁力 / 种子下载。HTTP 传输使用 .NET HttpClient；任务库使用 Microsoft.Data.Sqlite，BT 工作进程使用原生 libtorrent。

## 运行

安装 x64 .NET 10 Desktop Runtime 后，打开 `publish-auto-http/NetworkDownloader.exe`。自动并发版使用独立发布目录和 `NetworkDownloader-AutoHttp-win-x64.zip`，不会覆盖旧版任务中心。请完整解压发布包，不要单独移动 EXE；`bt-worker/` 是 BT 必需组件。旧版发布目录保留。
开发运行：

```powershell
dotnet run --project NetworkDownloader.App
```

1. 点击“新建下载”，输入 HTTP/HTTPS 文件直链、磁力链接、裸 Hash 或本地种子。
2. 选择以太网或 Wi-Fi 网卡，下拉列表和选中状态均只显示“网卡名称 · IPv4 地址”；HTTP 自动调整并发，无需手动指定连接数。
3. 选择保存目录，程序自动从下载地址路径末段解析文件名，点击“加入下载”。地址中的查询参数、片段不会包含在文件名中，中文和空格会解码；地址不含文件名时使用 `download.bin`。
4. 在列表中暂停、继续、重试或打开目录，Ctrl / Shift 可多选。暂停须等待引擎保存断点才完成；修改网卡须先暂停，再点“更换网卡”。同名成品及已排队任务的输出路径都会避让，不覆盖文件。
5. 网卡断开 / IP 改变时停止对应任务，不自动切换其他网络；关闭窗口会等待所有任务停止、刷新断点后退出。

文件名中的 Windows 非法字符会替换为下划线，保留名称会加下划线前缀。原有版本保存的完整文件路径会迁移为其所在目录。设置位于 `%LOCALAPPDATA%/NetworkDownloader/settings.json`，不保存带查询参数的地址；任务库通过当前 Windows 用户的 DPAPI 保存完整输入，因此列表里的签名链接可直接继续。注意：原有 `.part.json` 和 BT `resume.dat` 仍可能包含未加密 URL / Tracker 凭据，必须按敏感数据保管；任务库加密不等于所有下载目录都已加密。

## 下载任务中心

- 紧凑的左侧分类、虚拟化任务列表、可收起的底部详情；支持名称 / 网卡搜索、批量暂停 / 继续、仅移除记录和完成后打开目录。小窗口自动收起详情，按钮保持 32 DIP。
- 默认全局并行上限 3、BT 上限 1、每张网卡任务上限 2；超过任务限制排队，暂停完成后才释放执行名额。HTTP 不再预留每任务的手动连接数，而由共享控制器限制实际在途请求。配置在 `DownloadLimits` / `AdaptiveHttpOptions` 中，尚未提供图形化修改入口。
- `tasks.db` 使用 SQLite WAL、FULL 同步和版本校验。进度最多每 250 ms 合并到界面、每 3 秒落库，关键状态即时保存；任务状态事件不记录原始链接。单实例任务库锁防止多个新版窗口同时协调相同记录。
- 暂停、排队及意外中断的任务在重启后不会自动联网；意外中断显示“待恢复”。下载字节以引擎检查点为准，不使用界面的百分比推算续传位置。BT 的文件选择会自动沿用。
- 本地种子复制到用户数据目录的 `torrent-cache/`（有大小上限，元数据由 BT Worker 校验），原种子移动后仍可恢复。缓存、引擎断点及文件不会因“移除记录”而删除；本版不提供破坏性的批量删文件功能。
- 启动时检查完成任务的文件是否存在 / 大小是否变化；缺失只提示，不自动重下。数据库损坏、解密失败或写入失败不会静默建立空库，写入故障会停止调度并请求引擎停止保存。
- `tasks.db.bak` 是成功读取任务后、启动恢复前生成的 SQLite 在线快照，不是每次进度更新的实时镜像。保留数据库、WAL 及备份以便排查；关闭所有新版实例后才可从备份手动恢复。DPAPI 数据仅能由原 Windows 用户环境解密。
- 旧单任务版本没有历史目录，不能自动还原其下载历史。首次把原地址 / Hash 加入相同保存目录会复用现有 HTTP / BT 断点，无需删除旧文件。

界面采用紧凑布局，输入框、下拉框和按钮统一为 32 个设备无关像素高，文字、图标、圆角及间距同步缩小；长网卡名称可悬停查看完整名称和 IP。

## 磁力链接与种子下载

输入框支持 `magnet:?xt=urn:btih:...`、40 位十六进制 / 32 位 Base32 BT v1 Hash，以及本地 `.torrent` 文件完整路径。也可点击“打开种子”。BT v2 的 `urn:btmh:1220...` 链接交给原生引擎处理；本项目的自动传输验收首先覆盖 BT v1，不能把 v2 格式识别视为 v2 全链路已验收。HTTP 链接即使以 `.torrent` 结尾，也只下载该种子文件；下载后打开它，才会开始 BT 任务。

1. 在“新建下载”里选择网卡和保存目录，加入任务。裸 Hash 自动转换为磁力链接。
2. 种子文件直接读取元数据；磁力通过 DHT、Tracker 和 Peer 元数据交换寻找文件信息。格式有效不保证有在线节点或完整数据，无源时显示等待，可以随时取消。
3. 验证元数据后显示文件列表，选择要下载的文件。获取元数据阶段不下载内容分片。磁力 `dn` 仅为提示，文件名来自种子元数据。
4. 文件保存到所选目录的 `BT-<完整InfoHash>/`；其中保留种子原有文件名和子目录。未完成文件也会出现在此处，完成状态以应用校验结果为准。不要修改下载中的文件。
5. 暂停时等待磁盘刷新，并原子保存恢复信息。列表中“继续”会沿用已选文件；从旧版迁移也可加入相同 Hash / 种子与目录。恢复时保留未完成分片中的 16 KiB 数据块，并对记录为已完成的分片重新校验，不盲信完成标志。没有可用恢复记录时才全盘扫描，因此大文件恢复仍可能需要较长校验时间。

续传修复：不再每次开始都强制重扫并丢弃未完成分片的数据块；正确处理恢复位图末尾的字节对齐填充位。界面在读取恢复记录时显示“恢复中”，校验时显示“校验中”，不再将校验进度伪装成从 0 开始下载。旧版本保存的 `resume.dat` 可直接沿用，无需删除 `BT-Hash` 输出目录或 `.networkdownloader-bt` 状态目录。

BT 下载期间会向其他节点上传，默认上传上限 512 KiB/s，下载完成后停止做种。HTTP 自动并发不改变 BT Peer 策略；BT 当前上限 160 个 Peer 连接，连接建立速率 12 次/秒。使用异步引擎和稀疏文件，不使用 HTTP 的分片再合并方案。

任务状态保存在保存目录的 `.networkdownloader-bt/<InfoHash>/`，包含独占锁、所有权标识、文件选择与 libtorrent 恢复信息。请与输出目录一起保留；不要手动复制其他任务的状态覆盖它。恢复信息可能包含 Tracker 地址 / 凭据，应按敏感数据保管。应用设置不会保存磁力链接。

### BT 网络绑定与边界

- 每个任务使用独立工作进程和引擎会话，通过当前用户专用的随机命名管道与界面通信；不开放 Web 管理端口，不在命令行上传递磁力链接或 Tracker 凭据。
- `outgoing_interfaces` 绑定所选 IPv4 源 IP；`listen_interfaces` 同时绑定 Peer 入站、uTP、DHT 和 UDP Tracker 所用的监听地址。HTTP/HTTPS Tracker 使用引擎绑定的监听接口。禁用 IPv6 Peer、LSD、UPnP、NAT-PMP 和 Web Seed，不启用代理。私有种子的 DHT/PEX 限制由引擎执行。
- 网卡失效 / IP 变化每秒检测，检测后暂停并关闭会话。绑定失败会报告错误，不配置默认接口回退。DNS 仍使用系统解析器。
- **这不是 Windows WFP 级强制隔离**。BT 使用源 IP 绑定，不等同于现有 HTTP 的 `IP_UNICAST_IF`；VPN、弱主机模式、路由与过滤驱动仍可能影响实际物理出口。尚未完成真实双网卡下所有协议的抓包验收，不能承诺“零泄漏”。严格隔离需增加有管理员权限的系统级过滤，并独立验收。

### BT 安全与生产验收范围

拒绝符号链接种子、危险 Windows 路径、重复 / 冲突路径、保存目录中的目录联接；现有不属于任务的输出目录不会被接管。限制种子 / 磁力元数据至 4 MiB、文件数量至 10000、单文件至 8 TiB、总大小至 16 TiB；下载前检查可用磁盘空间。限制不能替代磁盘配额或操作系统沙箱，不支持其他不可信本地进程同时篡改目录的场景。

libtorrent 校验元数据与分片，协议校验不等于内容安全或来源可信。文件不会自动执行。只能下载和分享有权获取的内容。

当前已实现多任务队列 / SQLite 历史库，但不是已经通过企业生产认证的平台。WFP 强隔离、可配置上传 / 做种策略、长时压测、真实双网卡协议抓包，以及 BT v2 / 混合种子全链路专项验收尚未完成。工作进程异常时保留数据，再次继续会校验恢复，不会在后台无限重启。

### 构建完整 BT 版本

需要 Windows x64、.NET SDK 10、Visual Studio C++ 桌面开发工具和 CMake。首次构建联网下载 vcpkg / Boost / OpenSSL / libtorrent，编译产物都保存在忽略的 `artifacts/` 下。

```powershell
pwsh -File scripts/build.ps1
# 已有原生依赖时：
pwsh -File scripts/build.ps1 -SkipDependencies
```

脚本锁定 vcpkg 基线，编译原生桥接 DLL，构建 C#、执行测试，然后生成 `publish-auto-http/` 和 `NetworkDownloader-AutoHttp-win-x64.zip`。通过 `-Output` / `-Archive` 指定独立发布路径；不会覆盖已有同名压缩包。可通过 `-PerlPath C:\Strawberry\perl\bin\perl.exe` 指定完整的本机 Windows Perl。原生引擎静态链接其依赖，发布包附完整第三方许可证；不需要安装 vcpkg 或 C++ 编译器才能运行。

直接 `dotnet build` 不会联网构建 C++。未先构建原生 DLL 时，HTTP 仍可用，BT 会提示缺少引擎，不会伪装成功。测试程序的 BT 集成测试需要原生 DLL，使用本地生成的随机文件和本地种群，不连接用户提供的磁力资源。

## 网络选择的实现与边界

- `SocketsHttpHandler.ConnectCallback` 创建 IPv4 TCP Socket，设置 Windows `IP_UNICAST_IF`（网卡索引，网络字节序），并 `Bind` 到所选本地 IP，然后连接目标地址。
- 重定向建立的新连接仍使用同一个连接回调。所有分片均使用同一个绑定网卡的客户端；分片请求使用 HTTP/1.1，确保并行范围请求建立独立 TCP 连接。单连接下载也可使用 HTTP/2。禁用代理和 HTTP/3。系统路由表和其他应用不受修改，不需要管理员权限。
- 所选接口没有可用路由、网关或公网能力时下载失败；不会自动创建未绑定 Socket 来切换网络。应用不能绕过网络自身的访问限制。
- DNS 调用系统解析器，DNS 查询可能经过其他接口。VPN、企业过滤驱动以及系统隧道仍可能影响实际物理出口；本工具没有提供驱动级隔离。
- 当前支持 IPv4、有线 / Wi-Fi 列表、多任务排队和多连接分片下载。无 IPv4 的网络、纯 IPv6 服务器、网页解析、登录交互与下载限速尚未实现。
- 同一个 Socket 不能在连接中途切换网卡；暂停后重新连接，可使用新选择的网卡续传。

## HTTP 自动并发与分片下载

- 从 1 个请求开始，只测量真实下载数据，不访问外部测速站。每约 1 秒采样近期吞吐，采用指数平滑；每约 5 秒评估，增长探测至少间隔 12 秒。增加一个请求后的吞吐增益不足约 8% 时回退，延后约 36 秒再探测，避免持续加连接。
- 逻辑处理器数量只决定安全上限：单任务 `clamp(核心数×2, 2, 16)`，独立控制器默认全局 `clamp(核心数×2, 4, 32)`；应用再受 `DownloadLimits.MaxHttpConnections`（默认 16）约束。默认每网卡最多 16、每 Origin（协议 / 主机 / 端口）最多 8 个实际请求，多任务共享预算和公平份额；剩余分片少时实际请求数可以更低。
- 采样应用进程 CPU 占用、异步写入延迟及所选网卡 IPv4 接收流量（包含 BT / 其他程序）。CPU 达 85%、平滑写入延迟达 40ms 或网卡接近标称接收速率的 90% 时减半退让。标称链路速度只用于饱和保护，不当作公网带宽；写入延迟是应用侧压力指标，不等于物理磁盘队列长度或全系统 CPU 监控。
- 429 / 503 会减少并发，按 `Retry-After`（秒数或 HTTP 日期）对该 Origin 冷却，缺省采用递增等待；单次请求最多再试 3 次，反复限流后失败而非无限重试。冷却和预算等待不占在途名额，可随时暂停；网络 / 读取超时也触发退让。已有在途响应可能仍在排空。
- 预算覆盖探测、分片、单流、重试及重定向后的目标站点，直到响应体释放才归还名额；拒绝 HTTPS 降级重定向。预算统计的是实际 HTTP 请求，不是池中所有空闲 TCP Socket。多个任务不会各自独立扩张到全局上限。
- 详情显示“自动并发 · 当前 N 个请求”，状态文字解释测量、探测、收益回退或资源退让原因。历史任务库的旧 `Connections` 字段仅为兼容保留，新版忽略它；旧设置中的连接数也不再读取。

- 发出 `Range: bytes=0-0` 探测请求，只有服务器返回合法的 `206`、总长度及强 ETag / Last-Modified 时才启用分片。
- 文件小于 512 KB、服务器不支持范围请求、无法安全确认文件版本时，自动回退单连接。每个分片至少约 256 KB；新任务最多 16 个固定分片，分片数量不是当前并发数。
- 根据总长度划分连续、不重叠的字节范围，通过动态异步工作池逐步启动请求。各分片独立写入磁盘，进度和近期速度按所有分片汇总。
- 暂停、退出或传输中断后保留每个分片的已下载字节。恢复时验证远程版本并从每个分片的真实长度继续；已完成分片不重新下载。动态缩容仅取消需退出的 worker，等待其关闭文件；后续从真实文件长度恢复。已有分片布局不重排，兼容旧版 1–16 连接产生的断点。
- 文件版本变化时重新下载分片；服务器在探测后拒绝分片时，取消并等待其他分片停止，再安全回退单连接。旧版单连接临时文件仍以单连接方式续传，不丢弃已有进度。
- 每个分片分别检查 `Content-Range`、验证标识和实际长度，传输失败最多重试两次。任一分片发生不可恢复错误时取消其他分片，不生成成品。
- 全部分片完成后按字节顺序流式合并，再重命名为最终文件。合并中取消可在下次直接使用已完成分片重新合并。合并期间需同时保存分片和合并文件，临时磁盘空间约为文件大小的两倍。
- 下载任务使用独占临时锁，避免两个新版进程同时写入相同目标。分片目录只清理约定名称的临时文件，不递归删除未知文件。
- 多连接不保证成倍提速，实际速度取决于服务端限制、可用带宽和磁盘性能；只使用选择的网卡，不合并两张网卡的带宽。

## 文件完整性与恢复

- 使用流式 I/O 和 128 KB 缓冲区，不把大文件整体加载到内存。
- 使用强 ETag 或 Last-Modified 配合 Range / If-Range；没有验证标识时从头下载，避免混合不同版本。
- 只有合法的 `206 Content-Range` 才追加；`200` 从头下载，`416` 重新请求完整文件，不把现有临时文件直接判为成功。
- 校验续传偏移、范围、文件总长度、服务端返回的验证标识。声明长度不完整时不生成最终文件。未知长度响应以正常 EOF 为完成条件；没有服务端校验和时无法证明内容级完整性。
- 拒绝压缩传输，防止 Range 字节偏移和本地文件字节数不一致。HTTP 错误不会保存为成品文件。
- 连接 / 响应头约 20–30 秒超时，流式读取 30 秒无数据超时；传输错误最多自动重试两次，暂停可取消重试等待。
- 文件完成后在同一目录重命名 `.part` 为最终文件。续传需要保留元数据及相应的临时文件 / 分片目录，损坏或不匹配的元数据会报错。

## 项目结构

- `NetworkDownloader.App`：WPF / MVVM 任务中心、新建弹窗、分类、搜索、批量命令和详情。
- `NetworkDownloader.Core`：SQLite / DPAPI 任务库、状态协调、调度预算、网卡枚举、Socket 绑定、下载与续传。
- `NetworkDownloader.BtWorker`：独立 BT 工作进程、命名管道、网卡监测、文件选择和持久化恢复。
- `native`：libtorrent C ABI 桥接、网络绑定策略和锁定版本的原生依赖清单。
- `scripts/build.ps1`：依赖构建、全量测试、发布及许可证打包。
- `NetworkDownloader.Tests`：离线回归测试及 Windows Socket 集成测试。
